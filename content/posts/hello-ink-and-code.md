这是我第三次从头搭博客。

第一次用的是某个一键部署的框架，主题花了两天调到满意，然后写了三篇，弃了。第二次换成更花哨的那套，加评论、加访问统计、加暗色模式、加 PWA，最后加载要三秒，自己都不想打开。

这一次我给自己定了三条规则：

1. **不为工具花超过一天。** 一天之内跑不通，就说明这个方案不适合我。
2. **写作必须在一个文件里完成。** 打开编辑器，新建 `.md`，写，保存。没有后台，没有数据库，没有富文本编辑器。
3. **第一屏必须能看见字。** 不是动画，不是封面图，是字。

## 为什么之前会失败

回头看，前两次失败都不是技术问题。是我把博客当成了一个**作品**，而不是一个**习惯**。

> 作品需要打磨到可以展示的那一刻，习惯只需要今天也做了。

一旦是作品，你就会不断审视它："这个配色是不是不够高级"、"别人会不会觉得太简陋"。这种审视会消耗掉写的欲望——毕竟写一篇诚实的文章，比调一个阴影难多了。

## 这次的做法

这次我把整个站点压到极简：内容全是 Markdown 文件，一个两百行的 Python 脚本把它们编译成静态 HTML，没有任何前端框架，没有数据库。

好处是显而易见的：

- 打开电脑，`cd` 进目录，新建文件，写，`python build.py`，结束。
- 全文就是一个 Git 仓库，改错了 `git checkout` 就回来了。
- 十年后这些 `.md` 文件还能打开——这是我最在意的一点。

坏处也有：没有后台就不能在手机上写。但这其实是个**优点**，它天然过滤掉了那些"在通勤路上突然想写两句"的冲动——那种冲动九成写出来都是废话。

## 我打算写什么

三个抽屉：

| 抽屉 | 内容 | 频率 |
| --- | --- | --- |
| 技术笔记 | 学的东西，尽量写成三个月后自己还能看懂的样子 | 每周 |
| 项目复盘 | 做过的东西，重点记录取舍而不是成果 | 不定期 |
| 随笔 | 说不清楚归类的那些 | 想写就写 |

技术笔记最难写。因为它要求你真的懂了——把一件半懂的事写清楚，是骗不了人的。

## 最后

如果你也在犹豫要不要开始写，我的建议是：**先写一篇最烂的**。

不要设计系统，不要挑主题，不要想域名。打开任何一个能写字的地方，写五百字，发出去。你会立刻发现，真正难的不是搭建，是第二篇。

而第二篇的唯一前提是：第一篇的门槛足够低。
